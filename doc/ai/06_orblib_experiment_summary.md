# 06 — Эксперимент orblib_exp: удвоение, n_bin, библиотеки орбит (summary чата, авг–сент 2026)

## 1. Цель эксперимента
Проверить смещение результатов Шварцшильд-моделирования Fornax от:
1. **удвоения** данных — симметризации `(X,Y,vl) → (−X,−Y,−vl)`;
2. **числа звёзд на апертуру** `n_bin` (прод: 250);
3. (задел) реализации возмущения наблюдательных **GH-моментов** `gh_id`;
4. (задел) реализации возмущения параметров **Серсика** `ser_id`.

Побочная цель — сохранять **библиотеки орбит** для переиспользования.

## 2. Что реализовано
Новый скрипт `py/Fornax_P21_PCA_w3Sersic_orblib_exp.py` — копия
`Fornax_P21_symm_PCA_w3Sersic_yaVM_timed.py` с хирургическими правками.
Прод-скрипты не тронуты.

- Флаги: `--no-double`, `--n-bin` (250), `--gh-id`, `--ser-id`, `--save-orblib`,
  `--orblib-dir` (по умолч. `./orblib`).
- `gh_id>0` / `ser_id>0` осознанно падают `NotImplementedError` (реализован только
  номинал `0`) — чтобы не плодить фейковые «возмущённые» результаты.
- `EXP_ID = d{0|1}_nb{N}_gh{G}_ser{S}` вшит в `hostname_proc` → все производные файлы
  изолированы по эксперименту; пулинг PCA (`storage_patterns = out_*_{EXP_ID}_*.txt`)
  объединяет только **сравнимые** прогоны (penalty несравнимы между разными d/nb).
- Имена файлов: `out_{tag}.txt` — история (по строке на модель; её читают параллельные
  процессы); `log_{tag}.txt` — человекочитаемый лог `_write` (никем не читается).
- `pca_model_weighted_*.pkl` **больше не пишется**: файл был write-only (restore идёт из
  `checkpoint_*.pkl` с `X_obs/Y_obs/turbo`; параллельные процессы читают `out_*`).
- Сохранение библиотеки орбит (блок после `agama.orbit`):
  `orblib_i{incl:.1f}_d{D}_nb{NB}_ser{SER}_{md5(Q,gh,rh,rho0)[:10]}.npz`,
  `savez_compressed`, ключи `ic, inttime, matrix_dens, matrix_kinem, Q, gh, rh, rho0,
  incl, numOrbits, trajsize, intTime, gridv, degree, ghorder, n_bin, double, ser_id`.
  `skip-if-exists`, атомарная запись (tmp + `os.replace`). Сейчас матрицы **float32**.
  Размер логируется в консоль и в шапку `out`-файла.
- `.gitignore`: `py/orblib/`, `py/out_*.txt`, `py/log_*.txt` (не пересекаются с
  закоммиченными примерами `4Ups*`/`4result*`).
- Проверка: `python3 -m py_compile` — OK. Прод-запусков не было (§8).

## 3. Ключевой физический инвариант (не путать!)
- `gh` — **гамма гало**, параметр поиска (разный у каждой модели).
- `gh_id` — реализация возмущения **наблюдательных** Gauss–Hermite моментов.

Матрицы орбит зависят от `(Q, gh, rh, rho0, incl, double, n_bin, ser_id)`, но **НЕ от
`gh_id`** (тот меняет лишь `cons_val/cons_err` датасета). Поэтому одна библиотека
переиспользуема для всех `gh_id`; имя `.npz` и tar-ключ `gh_id` не содержат.
Орбитные IC стохастичны (RNG AGAMA) → для одних параметров содержимое у разных
процессов различается; одной реализации достаточно (first-wins).

## 4. Согласованный дизайн хранения/синка библиотек
- **Lookup только локальный** (файлы в `ORBLIB_DIR`); сети в горячем цикле нет.
  Межмашинное распространение — целиком на оркестраторе.
- **Tar-шарды** на Я.Диске (`REMOTE_DIR=galAgama`), несжатый `.tar` (внутри `.npz` уже
  сжаты): `orblib_i{incl:.1f}_d{D}_nb{NB}_ser{SER}__{HOSTNAME}_{TIMESTAMP}.tar`.
  Общий префикс-ключ эксперимента, уникальный суффикс запуска → разные имена для разных
  запусков, ничего не перезаписывается, повторно ГБ не гоняются.
- Перед запуском процессов: скачать все шарды по ключу, **распаковать один раз** в
  `ORBLIB_DIR` (union, дедуп по имени `.npz`), снять snapshot списка файлов.
- После завершения: `new = after − before` → tar только новых → залить новый шард.
- Синка библиотек **в процессе** нет (§10 касается истории `out_*`, не библиотек).
- Консолидация шардов — отдельный опциональный оффлайн-шаг.
- Решено: переход на **float64** при сохранении (воспроизводимость penalty при reuse).

## 5. Переданные/запланированные задачи (отдельные запросы)
1. **Reuse-lookup** в `halo_IC_lib_weights_pca_fixed`: флаг `--reuse-orblib` (OFF),
   общий helper ключа для save/lookup, проверка метаданных, float64.
2. **Отдельный оркестратор** `launch_orblib_exp.sh` (новый файл, прод
   `launch_docker_parallel.sh` не трогать): `--script=..._orblib_exp.py`, новые имена
   `out_*`/`log_*`, ШАГ 0 pre-download+unpack, финал snapshot-diff → tar → upload.
3. **Нужен ли `ic`/`inttime` в `.npz`**: предварительный анализ — единственный
   потребитель `agama.orbit`, который reuse пропускает; после него `ic`/`inttime` не
   используются. Ведущая гипотеза — не хранить (вариант A); подтвердить кодом
   (J-фактор, диагностика), измерить экономию. Различать checkpoint-resume (не трогает
   библиотеки) и orblib-reuse.

## 6. Важное наблюдение о прод-файлах
`Fornax_P21_symm_PCA_w3Sersic_yaVM_timed.py` (3492 стр.) отличается от
`..._yaVM.py` (3175 стр.) **не только таймингом**. Кроме `perf_counter`/`solveopt_times`
он содержит **оптимизации Brent-поиска по Upsilon**: адаптивная скобка вокруг
предсказанного `Upsilon*` (`_ups_recent`), субдискретизация орбит во внутреннем поиске
(`UPS_SUBSAMPLE_FRAC=0.25`) с финальным full-solve, толеранс `UPS_XATOL=5e-3`
(в проде `1e-3`). Это затрагивает §7 контракт (Brent по Upsilon). Резервации точек
есть в обоих. `orblib_exp.py` унаследовал эти оптимизации от `_timed`.
